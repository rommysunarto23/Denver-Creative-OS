## Two holes Ideal V0.2 left open (why R1)

### Hole A — Identity Lock circularity (Candidate B)

```text
single angled source
  -> AI generates identity lock / front view
  -> lock passes visual comparison
  -> lock becomes authority
```

AI must not **create evidence that did not exist**, then use that invention to "prove" novel geometry.

### Hole B — SOURCE_PRESERVE not raster-safe

If the cutout is sent to ChatGPT Images and the model may edit/relight the **whole** image, product pixels can still change. That is not true preserve.

## Six deltas (full)

### Delta 1 — Identity Lock is not ground truth

Rename semantically to something like `canonical_render` / `generation_lock`.

- May act as a **generation stabilizer**.  
- Must **not** alone promote `UNVERIFIABLE → PASS`.  
- Every lock carries authority metadata:

```yaml
authority:
  type: DERIVED_RENDER
  evidence_basis:
    - source-01
  can_establish_new_geometry: false
```

For `NOVEL_VIEW`, new geometry may `PASS` only when **original** evidence supports it: multi-view source, straight/front reference, measured dimensions, CAD/3D, or client-supplied evidence. Generated lock does **not** create new facts.

### Delta 2 — SOURCE_PRESERVE must truly preserve product raster

Contract split:

```text
generative model owns:
  background / environment / props / scene

original cutout owns:
  product pixels / silhouette / geometry
```

Product region must **not** be repainted by ChatGPT Images. For zero-cost MVP:

- Scene may be generated manually in ChatGPT Images.  
- Final product placement uses **deterministic local compositing** of the original cutout (e.g. light helper: Pillow / OpenCV / ImageMagick) plus controlled shadow/integration.  
- Hermes remains orchestrator.

**ChatGPT paste: this is the most important delta for Alex/ITWR.**

### Delta 3 — `SHOT_FEASIBILITY_GATE` before generation

```text
requested shot
  -> SUPPORTED_VIEW | PARTIAL_VIEW | NOVEL_VIEW
  -> evidence sufficient?
```

If client asks straight-on but only supplies angled source:

```text
NOVEL_VIEW + INSUFFICIENT
  -> NEEDS_EVIDENCE
```

— not four blind generate attempts.

Hermes may offer:

```text
provide front / multi-view evidence
OR choose supported alternative shot
OR run experiment-only novel generation
```

### Delta 4 — Multidimensional release gate

Not only `product_fidelity`, but:

```yaml
presentation_quality: PASS | FAIL | ...
product_fidelity: PASS | FAIL | UNVERIFIABLE
shot_compliance: PASS | FAIL
evidence_sufficiency: SUFFICIENT | INSUFFICIENT
release_eligibility: ELIGIBLE | BLOCKED | NEEDS_EVIDENCE
```

Client release requires:

```text
product_fidelity = PASS
AND shot_compliance = PASS
AND evidence_sufficiency = SUFFICIENT
AND no critical artifact
  -> RELEASE_ELIGIBLE
```

Then human may set `RELEASE_APPROVED`. Human **cannot** rewrite `FAIL` → `PASS`.

Experiment path remains:

```text
package_class: EXPERIMENT_ONLY
human_disposition: EXPERIMENT_ACCEPTED
```

— never `CLIENT_RELEASE`.

### Delta 5 — Golden fixtures: static + oracle-labelled; 9/9

Raise from "3 fixtures once" to:

```text
3 paths × 3 repeated Sol Medium runs = 9/9 expected outcomes
```

| Path | Construction | Expected |
|------|--------------|----------|
| POSITIVE | Exact source-preserved geometry (new fixture; not disputed SHOT-01) | PASS → RELEASE_ELIGIBLE |
| NEGATIVE | Obvious controlled product mutation | FAIL → RELEASE_BLOCKED |
| AMBIGUOUS | Critical attribute hidden / unsupported novel view | UNVERIFIABLE → NEEDS_EVIDENCE |

**100% PASS** means: every test yields the **expected decision** 100% of the time — not "every candidate is accepted."

Positive fixture ideally = SOURCE_PRESERVE composite with construction-identical geometry.

### Delta 6 — Harder checkpoint return gate

Stay at (or move to):

```text
MVP_REOPENED_FOR_FIDELITY_CONTRACT_V02
```

Return to `MVP_READY_FOR_PITCH_PREPARATION` only when **all** hold:

```text
schema v0.2(-R1) valid
+ POS 3/3
+ NEG 3/3
+ AMB 3/3
+ SOURCE_PRESERVE end-to-end PASS
+ client-release override impossible
+ NOVEL_VIEW insufficient evidence routes NEEDS_EVIDENCE
+ Image API spend = $0
```

**NOVEL_VIEW need not produce a final straight shot to close MVP.** Correct decision under insufficient evidence (`NEEDS_EVIDENCE`) is a **success**, not a system failure.
